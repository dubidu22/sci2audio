# Changelog

All notable changes are listed here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and versions follow [Semantic Versioning](https://semver.org/).

## [Unreleased]

### Added

- German voice (#211, VA-07): Kokoro Thorsten (`dm_thorsten`), the Kokoro model fine-tuned by Thorsten-Voice on the CC0 Thorsten-Voice dataset (Apache-2.0), reads German texts offline; pronunciation by espeak-ng, no text rewritten in the voice (D-467, D-470). The voice download comes in one pack per language (`voices download --language`), a job needs only its own language's pack, and a text is read by the chosen voice if it speaks the text's language, else by that language's default voice (D-468, D-469). The German weights are renamed on load and checked weight by weight, because kokoro 0.9.4 would otherwise skip some of them silently and speak noise.
- The text's language is guessed when the file states none (#219): sci2audio counts common German and English words over the whole text and reads it in German or English when one outnumbers the other at least 3 to 1 (at least 20 such words), so an untagged German PDF gets the German voice and the German rules without `--language de` (D-494, D-495). A file tagged English or German whose text is clearly the other language is read in the text's language, with a warning (D-496). Your language setting always wins. The report, the command line and the document page say where the language came from; a text too short or too mixed to tell is read in English with a warning (D-497 to D-500).
- A real German paper in the test corpus (#235): "PrivacyScore" by Maass, Laubach and Herrmann (arXiv 1705.08889, CC BY 4.0), with its hand-checked truth file, so German layout is tested on a real file (D-511, D-512). Reading it showed three layout gaps, now fixed: running heads of a text set in a small type area on bigger paper (the LNI template of German computer science) are found, because when nothing is printed in the paper's top tenth the first printed row counts as the page's top (D-502 to D-505); German captions ("Abb. 1:", "Tabelle 2:", "Tab.", "Algorithmus") name their figures and tables in any document (D-506); and footnote marks set as raised figures in the notes' own size start their notes (D-507).

## [1.0.0] - unreleased

The first release. sci2audio turns a scientific text (PDF, EPUB, Markdown or plain text, in English) into a faithful audiobook on your own computer: a listening script with every change marked and explained, MP3 files per chapter and an M4B with chapters, and a read-along player that highlights the original text. Everything runs offline after one voice download you start yourself.

### Added

#### Reading files

- PDF extraction (#23): records each page's text lines with font, size, bold, italic and position, its pictures and drawings, and the file's metadata as `Content`, deciding nothing (D-63, D-65); damaged, empty and password-protected files are refused with a clear message.
- Bold and italic from CM-Super and EC font names (#45), the T1 Computer Modern of most LaTeX papers, read from the cut in the name (`SFBX1095`, `SFTI1095`) as the cm-super font files define it.
- Outline in `Content` (#24, part 1): `Content.outline` keeps the file's own outline (PDF bookmarks, later an EPUB's table of contents) as `OutlineEntry`s with title as stored, level and target page, in the file's order, as a hint for headings (D-262 to D-266).
- PDF bookmarks (#24, part 2): PDF extraction records the file's bookmarks in `Content.outline`, in the file's order with their levels and target pages, titles exactly as stored; a GoTo action counts as a target, and a damaged outline gives what could be read without failing the file (D-266 to D-268).
- Content without positions (#73, part 1): `Page.order` keeps the stored order of lines and pictures where items have no boxes (EPUB, Markdown), `Picture.ref` where the file stores an image, and `OutlineEntry.item` the item an outline entry's anchor points at; all empty by default, so PDF content is unchanged (D-309 to D-311).
- EPUB extraction (#73, part 2, IN-02): each spine document becomes a page, each block element a text line with its markup as tags (element names, ids, `epub:type`, roles, language, links resolved to the item they point at), bold and italic from the HTML default rendering, pictures with their place, path and alternative text, the table of contents (navigation document or NCX) as the outline, and the package's title, authors, date, identifier and language, with the standard library only (D-304 to D-312). Damaged, encrypted, DRM-protected and oversized EPUBs are refused with a clear message (D-315). Cover images for the audiobook (OU-01): the cover an EPUB declares, or a PDF's first page as a PNG (D-313).
- Markdown and plain text (#74, IN-03): Markdown is read as CommonMark with tables, strikethrough, footnotes, dollar maths and front matter, through the same page reader as EPUB; a text file's encoding is guessed and `Source` names how its bytes were read (D-337 to D-352). Broken, oversized and binary files are refused with a clear message.
- Hostile and broken PDFs (#5, IN-01): golden files for the corpus papers and a set of broken files; scanned pages without a text layer, files cut short, locked files and files built to exhaust memory or time are refused with a message that says why, inside item and time limits (D-393 to D-404, D-419).

#### Layout: reading order, blocks and sections

- Layout (#21, IN-01): a new pipeline stage turns the extracted `Content` into a `Document` in reading order (D-63, D-67). Page furniture (running heads, page numbers, footers, line numbers, side stamps, a printed table of contents, a sidebar) is found and kept apart with its role, and each page's printed page number is kept as its label (#31). Columns are found band by band and read one after the other. Lines split by extraction are joined again, and paragraphs continue across columns and pages (#27).
- Block kinds and sections (#21): headings with their levels and printed numbers, and the section tree; footnotes with their marks, one block per note (#37); captions with their labels and list items with their markers; tables, figures and algorithms as placeholders their captions name (#38, #51); display formulas as placeholders with their printed numbers, a formula across both columns read once (#34).
- Outline as a heading hint (#24, part 3): layout uses the file's outline after the font rules: an entry adds a heading the font rules missed when exactly one paragraph on its page has its title as its whole text, and never removes a heading or changes its level; a single top entry naming the document is skipped (D-270 to D-272).
- A space between line pieces only where the page prints one (#36): a footnote mark, subscript or stacked script no longer reads as a word of its own.
- Running heads (#33): a body-size line at the top or bottom of two pages is a running head only when its exact text repeats on most pages, so "Algorithm 1" or a repeated table header stays in the text.
- Loose rules and marks (#58, #123, #163): a rule or small mark drawn inside a line stays in that line's block and no longer cuts its paragraph; a drawing on an algorithm caption's line stays with that caption.
- A heading with a rule drawn under it across the text width is a level-1 heading (#48).
- Documents without positions (#75, IN-02, IN-03): EPUB, Markdown and text are read from their tags (headings, paragraphs, lists, tables, figures, notes), not with the PDF rules; any EPUB navigation is furniture (D-405 to D-418, D-429). Blocks stay in page order after a paragraph is cut (#196).

#### Text rules: what the listener hears

- Text-step interface (#63, PE-10): text steps propose marked edits (remove, replace, pause, ask) with a reason, and the runner applies them in a fixed order; nothing rewrites text silently and nothing summarises (D-57). Every rule can be switched off by its category. The listening script is cut into utterances the voice can speak, keeping each one's place in the original text for read-along.
- Furniture, formulas, tables, figures, footnotes and the reference list (#64): page furniture is left out; formulas, tables and figures get a short spoken notice that names them; footnotes are read where their mark stands, as "Footnote 1." and its text; the reference list is left out by default.
- Characters and hyphenation (#65, IN-04): ligatures, mathematical letters and digits, soft hyphens and stray accents read as plain letters; a word hyphenated at a line end is joined again by one written rule, checked on every line-end hyphen of the corpus papers (TP-02).
- Citations, URLs, DOIs and e-mail addresses (#66): numbered and author-year citations, links, DOIs, arXiv numbers and e-mail addresses are left out with a marked edit, and the sentence around them still reads (D-167 to D-176). Footnote marks in EPUB and Markdown are tied to their notes by link tags (#189).
- Abbreviations, symbols and units (#68): read as words only where the voice would read them wrong ("e.g.", "Fig.", "mg/kg", "m²"), measured on the voice itself first (D-227 to D-243).
- Numbers, dates and statistics (#67): comparison operators, ± and minus signs, ranges, counts, powers of ten, test statistics with their degrees of freedom, R² and χ², confidence intervals and odds ratios read as the voice should; ordinary numbers, years and dates are left to the voice, which reads them well (D-176 to D-190).
- An abbreviation glued to a bracket no longer ends a sentence (#91).
- Reading rules sharpened in review (#109, #110, #145, #151, #159, #160): a URL cut at a line end no longer swallows an ordinary word on the next line ("and", "the"); a name with "the", "a" or "an" before it keeps its year in brackets ("the Olympics (2016)"); a bracket that holds only a citation and its lead words goes whole ("(See Smith (2019).)"); confidence intervals joined by "and", "or" or a comma are all read as intervals; units glued to a number or behind characters that are not spoken are read on the first run; an accent set apart from its letter and a size such as "5 x86K" read the same on every run.
- First German rules, ahead of v1.1 (#96, #221): German line-end hyphens (suspended hyphens before "und", "oder" and the like stay; split words are joined) and German reference-list titles ("Literatur", "Quellen", "Bibliographie" and others) when the job's language is German.

#### Voice

- Kokoro English voice (#18): the voice plugin contract and Kokoro plugin copied from Abogen (MIT, D-52) on PyTorch (D-48), 28 English voices with speed and a preview sample, 16-bit mono WAV files for the output stage, and one user-started download of everything needed offline (model, voices, spaCy English model), pinned by checksum and safe to interrupt (D-47, VA-03, VA-04). Conformance suite for voices in `sci2audio.testing`; nightly speech-recognition round trip and speed benchmark.
- Speed script and performance budget (#11, VA-02): `scripts/speed.py` measures the voice on the CPU and on the GPU (MPS), `docs/baseline.md` holds the budget, and the nightly run keeps the script working.

#### Audiobook

- Output (#69, OU-01, OU-03): one MP3 per chapter and one M4B with chapter marks, cover, title, authors, language and a label that says the voice is AI-generated; the read-along file ties each sentence to its place in the audio. ffmpeg comes with the `imageio-ffmpeg` package, with an ffmpeg on PATH as a fallback.
- The script job (#70, UC-01, UC-03): a file in, the listening script and a report of every change out, without a voice; chapters are the document's top-level sections, chosen by number. The report numbers chapters from 1, as the interface and the command line do (#104), and shows a line break inside a quoted edit as “↵” (#118).
- The audio job (#71, WI-02, VA-04): a file in, the audiobook out, entirely offline; an interrupted run resumes from its speech cache. The time left is estimated from a cost per spoken chunk fitted on the run (#136, D-380 to D-383).
- EPUB files in the app (#73, part 3, IN-02, OU-01): the script and audio jobs, the command line and the web interface read `.epub` files; the audio job writes the file's cover (an EPUB's declared cover, a PDF's first page) to the working folder and puts it into every MP3 and the M4B. A file without a usable cover, or a cover that cannot be written, gives an audiobook without one, never a failed job (D-313).
- Markdown files, text files and pasted text in the jobs, the command line and the interface (#74).

#### Command line

- Command line (#72, WI-03): `sci2audio script`, `convert` (resumes an interrupted run), `voices` with `voices download` (shows every file, size, licence and host and asks first, VA-03) and `clean`; chapters counted from 1, text-step categories switched with `--on`/`--off`, the settings file read as defaults, documented exit codes, Ctrl-C stops after the current sentence (D-210 to D-226). CI runs `sci2audio script` on a corpus PDF on Linux, macOS and Windows on every PR; a nightly test runs `sci2audio convert` with the real voice, killed and resumed (PE-02).

#### Interface and player

- Local server and job API (#76): `sci2audio ui` serves the interface on 127.0.0.1 only, at a port the system picks, behind a start-up token, with Host, Origin and Sec-Fetch-Site checks against other pages in the browser (D-192 to D-194). A JSON API under `/api/v1` opens files and pasted text, runs the pre-analysis, keeps the settings, lists the voices and starts the voice download only with consent to the exact download shown (D-197 to D-203), with progress as server-sent events. FastAPI's built-in OpenTelemetry is switched off (D-195). Tested with TestClient and Schemathesis (#7).
- The interface (#77, UC-01 to UC-03, AQ-01): a start page to open a file and see the documents opened before; a document page in three steps (check the analysis and its report, choose chapters and what is read, make the audiobook); the voice download with consent to the exact files shown; progress and a time estimate while it works; a job page with the result. Every page works with the keyboard alone and passes axe-core checks, in Chromium, Firefox and WebKit (#8, #205).
- Read-along player (#78, OU-02): a Listen page per document plays the audiobook chapter by chapter and shows the original text as printed, highlighting the sentence being read, scrolling with it until you scroll away, and playing from any sentence you click; skipped formulas, tables and figures show the notice the audiobook reads, printed page numbers mark where pages start, and a line names the synthetic voice. Every control is a button for the keyboard, nothing is announced while it plays, and the files are served only from the folder the audiobook was written to after checking they belong to it (D-294 to D-303).
- English and German interface and the privacy page (#79, AQ-02, AQ-03): every interface string in one table per language with the same keys (`web/strings/en.toml`, `de.toml`); the language comes from a switch on every page (remembered in a cookie), else the browser's language, else English (D-288 to D-292). Spoken words and the app's own messages stay English and are marked as such for screen readers (D-50, D-291). `/privacy` states what stays on the computer, with the download hosts and folders of the running server (D-293).
- Removing a document (#120, AQ-03, WI-02): the start page and each document's page offer “Remove this document”, a disclosure that says what goes (the copy of the file, its analysis and the speech cache, with their size) and what stays (the audiobook, in its folder, and the file you opened); the press of its button removes the document's whole working folder and nothing outside it. `DELETE /api/v1/documents/{id}` answers 409 while a job works on the document, here or in another process, and a removal that fails part-way names what is left and keeps the document listed for another try (D-353 to D-363).

#### Privacy and security

- Nothing leaves your computer: no account, no upload, no telemetry, no crash reports. The only network access is the voice download you start, pinned by checksum. The server binds to 127.0.0.1 only.
- OWASP ZAP baseline scan (#12, AQ-03): `scripts/zap_scan.py` starts the server with the test fakes, walks the main flow in Chromium through ZAP in English and German (open files, analysis, voice download, preview, audiobook, player, every API route, the 401 and 421 answers), lets ZAP crawl it, and fails on any High or Medium alert, on a Low one not accepted with a reason in `scripts/zap/accepted.toml`, and on any route or page language it never saw (D-364 to D-372). It runs in its own workflow on PRs that touch the server, nightly and by hand; the release checklist asks for its last run on `main`.

#### Development

- Project setup (#1): package layout in layers, CI on Linux, macOS and Windows, licence and layer checks, contributor and agent guidelines.
- Testing pipeline (#2, D-58): property-based tests (Hypothesis), golden files (syrupy), security checks (Ruff security rules, pip-audit, zizmor), nightly slow tests and benchmarks, manual mutation testing (mutmut), release checklist and listening-test template.
- Sample corpus and ground truth (#3, #16): seven openly licensed papers and one EPUB with hand-written truth files of what a listener should hear; layout and text steps are measured against them.
- Development and process (no change for users): core data objects for extracted content and the reading document (#17); corpus truth sentences with footnote marks and inline maths (#39); test strategies that build overlapping spans (#47); axe-core waits for the page's stylesheet (#129); the same-day quarantine of flaky tests (D-374) and the fixes that emptied it (#138, #147, #157, #161, #166); layout properties for sections without positions and tagged base levels (#195, #199); review, merge and plan rules for agents in `CLAUDE.md` (D-68 to D-72, D-80).
- The release workflow installs the built package on Linux, macOS and Windows and runs it on a corpus PDF before it publishes to PyPI, then installs the release from PyPI on all three (#80).
